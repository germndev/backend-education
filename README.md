# Backend Education

Домашние задания по курсам PurpleSchool. Один репозиторий для ПК (Windows) и Mac.
Каждый курс находится в своей папке, каждое задание — в отдельной папке курса.

```text
backend-education/
├── js-basic/          # JavaScript для начинающих
│   ├── 4-navigator/
│   ├── 5-languages/
│   ├── 6-driver/
│   ├── 7-converter/
│   ├── 8-crypto/
│   ├── 9-sort-loops/
│   ├── 10-array-clean/
│   └── 11-date-array/
└── README.md
```

Новые курсы добавляем рядом с `js-basic`, новые задания — внутри папки своего курса.
Существующие решения и история коммитов сохранены. Основная ветка — `main`.

## Подключение второго устройства

Установи Git и редактор. В терминале перейди в папку, где хранишь проекты:

```sh
git clone https://github.com/germndev/backend-education.git
cd backend-education
git config pull.ff only
git config fetch.prune true
git config core.autocrlf false
```

Для авторства коммитов настрой имя и email в этой копии репозитория:

```sh
git config user.name "Твоё имя"
git config user.email "Твой email из GitHub"
```

При первой отправке изменений авторизуйся в GitHub через менеджер учётных данных.
Если он не настроен, используй SSH или personal access token; пароль аккаунта для Git не подходит.
Не сохраняй токены в файлах проекта или URL репозитория.

На текущем ПК репозиторий уже находится в папке `backend-education`; повторно клонировать его не нужно.
На Mac держи отдельную копию, например в `~/Projects/backend-education`.
Между устройствами передавай изменения через GitHub, не через синхронизацию папки `.git` в OneDrive/iCloud.

## Каждый раз перед работой

На том устройстве, за которым сейчас работаешь:

```sh
git status
git pull --ff-only
```

Начинай работу после успешного получения изменений. Если остались незакоммиченные правки,
сначала сохрани их коммитом или временно убери через `git stash`.

## После работы и перед сменой устройства

```sh
git status
git add .
git diff --cached
git commit -m "js-basic: выполнено задание 12"
git push
```

Перед коммитом проверь список и содержимое изменений. После успешного `push` изменения доступны второму устройству.
Один `commit` сохраняет их только локально. Незавершённое задание тоже можно сохранить, например
с сообщением `js-basic: черновик задания 12`.

Если оба устройства успели создать новые коммиты и `pull --ff-only` отказался обновляться,
сохрани местные правки коммитом и выполни `git pull --rebase`. При конфликтах исправь отмеченные Git файлы,
добавь их через `git add <путь>` и выполни `git rebase --continue`, затем `git push`.
Для отмены незавершённого rebase используй `git rebase --abort`. Не используй `push --force` для синхронизации.

## Проверка заданий

У существующих заданий есть `index.html`: открой его в браузере и смотри результат в консоли разработчика.
Установка npm-пакетов для этих заданий не требуется.

Когда в будущих курсах появятся проекты Node.js, фиксируй версию Node в проекте и сохраняй
`package.json` и lock-файл в Git. Зависимости устанавливай отдельно на каждом устройстве
(`npm ci`, если есть `package-lock.json`). Папка `node_modules` и локальные `.env` в Git не попадают.

## Общие настройки

`.gitattributes` задаёт LF для текстовых файлов на обеих системах, `.editorconfig` и
`.vscode/settings.json` — UTF-8, пробелы и одинаковые переносы строк.
Настройки `git config` локальны: на новом устройстве их нужно выполнить заново.

Ветка `dev` из старого репозитория сохранена. Для новых заданий с проверкой через pull request
создавай ветку от обновлённой `main`, например `git switch -c js-basic/task-12`,
а после коммита отправляй её командой `git push -u origin js-basic/task-12`.
Чтобы продолжить эту ветку на другом устройстве, выполни `git fetch origin`,
`git switch js-basic/task-12` и `git pull --ff-only`.
