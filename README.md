# Backend Education

Домашние задания по курсам PurpleSchool. Один репозиторий для ПК (Windows) и Mac.
Каждый курс находится в своей папке, каждое задание — в отдельной папке курса.

```text
backend-education/
├── js-basic/          # JavaScript для начинающих
│   ├── 4-navigator/
│   ├── 5-languages/
│   ├── 6-driver/
│   ├── 7-converter/
│   ├── 8-crypto/
│   ├── 9-sort-loops/
│   ├── 10-array-clean/
│   ├── 11-date-array/
│   └── 12-luna/       # В ветке 12-luna
└── README.md
```

Новые курсы добавляем рядом с `js-basic`, новые задания — внутри папки своего курса.
Существующие решения и история коммитов сохранены. Основная ветка — `main`.

## Подключение второго устройства

Установи Git и редактор. В терминале перейди в папку, где хранишь проекты:

```sh
git clone https://github.com/germndev/backend-education.git
cd backend-education
git config pull.ff only
git config fetch.prune true
git config core.autocrlf false
```

Для авторства коммитов настрой имя и email в этой копии репозитория:

```sh
git config user.name "Твоё имя"
git config user.email "Твой email из GitHub"
```

При первой отправке изменений авторизуйся в GitHub через менеджер учётных данных.
Если он не настроен, используй SSH или personal access token; пароль аккаунта для Git не подходит.
Не сохраняй токены в файлах проекта или URL репозитория.

На текущем ПК репозиторий уже находится в папке `backend-education`; повторно клонировать его не нужно.
На Mac держи отдельную копию, например в `~/Projects/backend-education`.
Между устройствами передавай изменения через GitHub, не через синхронизацию папки `.git` в OneDrive/iCloud.

## Каждый раз перед работой

На том устройстве, за которым сейчас работаешь:

```sh
git status
git pull --ff-only
```

Начинай работу после успешного получения изменений. Если остались незакоммиченные правки,
сначала сохрани их коммитом или временно убери через `git stash`.

## После работы и перед сменой устройства

```sh
git status
git add .
git diff --cached
git commit -m "js-basic: выполнено задание 12"
git push
```

Перед коммитом проверь список и содержимое изменений. После успешного `push` изменения доступны второму устройству.
Один `commit` сохраняет их только локально. Незавершённое задание тоже можно сохранить, например
с сообщением `js-basic: черновик задания 12`.

Если оба устройства успели создать новые коммиты и `pull --ff-only` отказался обновляться,
сохрани местные правки коммитом и выполни `git pull --rebase`. При конфликтах исправь отмеченные Git файлы,
добавь их через `git add <путь>` и выполни `git rebase --continue`, затем `git push`.
Для отмены незавершённого rebase используй `git rebase --abort`. Не используй `push --force` для синхронизации.

## Проверка заданий

У существующих заданий есть `index.html`: открой его в браузере и смотри результат в консоли разработчика.
Установка npm-пакетов для этих заданий не требуется.

Когда в будущих курсах появятся проекты Node.js, фиксируй версию Node в проекте и сохраняй
`package.json` и lock-файл в Git. Зависимости устанавливай отдельно на каждом устройстве
(`npm ci`, если есть `package-lock.json`). Папка `node_modules` и локальные `.env` в Git не попадают.

## Общие настройки

`.gitattributes` задаёт LF для текстовых файлов на обеих системах, `.editorconfig` и
`.vscode/settings.json` — UTF-8, пробелы и одинаковые переносы строк.

### Настроить Git на устройстве

Выполняй команды в терминале из папки `backend-education`. Эти настройки относятся
только к текущему репозиторию: на втором устройстве их нужно повторить.

| Команда | Что делает |
| --- | --- |
| `git config user.name "Твоё имя"` | Задаёт имя автора коммитов. |
| `git config user.email "Твой email из GitHub"` | Задаёт email автора коммитов. |
| `git config pull.ff only` | Разрешает обычный `pull` только без объединения разошедшейся истории. |
| `git config fetch.prune true` | При `fetch` убирает локальные ссылки на удалённые с GitHub ветки. Локальные рабочие ветки сохраняются. |
| `git config core.autocrlf false` | Отключает автоматическую замену LF на CRLF; переносы задаёт `.gitattributes`. |
| `git remote -v` | Показывает адрес GitHub-репозитория. `origin` — имя этого удалённого репозитория. |

### Посмотреть состояние и изменения

| Команда | Что делает |
| --- | --- |
| `git status` | Показывает текущую ветку, изменённые файлы и подготовленные к коммиту правки. |
| `git diff` | Показывает правки в отслеживаемых файлах, ещё не добавленные через `git add`. Новые файлы смотри через `git status`. |
| `git diff --cached` | Показывает правки, которые войдут в следующий коммит. |
| `git log --oneline -10` | Показывает последние 10 коммитов текущей ветки. |
| `git branch` | Показывает локальные ветки; текущая отмечена `*`. |
| `git branch -a` | Показывает локальные ветки и известные ссылки на ветки GitHub. |

### Создать ветку для нового задания

Имя ветки совпадает с именем папки задания: для `js-basic/12-luna` это `12-luna`.
Каждую новую ветку создавай от обновлённой `main`:

```sh
git switch main
git pull --ff-only
git switch -c <имя-папки>
```

Замени `<имя-папки>` на имя нового задания без угловых скобок.
`git switch` переключает ветку, а флаг `-c` создаёт новую и сразу переключает на неё.
Перед переключением сохрани текущие правки коммитом или через `stash`.

### Сохранить работу и отправить на GitHub

```sh
git status
git add .
git diff --cached
git commit -m "12-luna: выполнено задание"
git push -u origin 12-luna
```

`git add .` подготавливает все изменения внутри текущей папки к коммиту.
Для отдельного файла используй, например, `git add js-basic/12-luna/app.js`.
`git commit -m` сохраняет подготовленные правки локально с указанным сообщением.
`git push` отправляет коммиты на GitHub.

При первой отправке новой ветки используй `git push -u origin <имя-папки>`:
флаг `-u` связывает локальную ветку с веткой на GitHub. После этого достаточно `git push`.
Для уже настроенной ветки `12-luna` тоже достаточно `git push`.

### Продолжить задание на другом устройстве

Сначала выполни `commit` и `push` на устройстве, где работал. На втором устройстве:

```sh
git fetch origin
git switch 12-luna
git pull --ff-only
```

`git fetch origin` получает сведения о ветках и коммиты с GitHub, сохраняя текущие рабочие файлы.
`git switch 12-luna` открывает локальную ветку; если её ещё нет, Git создаст её
из одноимённой ветки `origin`. `git pull --ff-only` получает и применяет обновления текущей ветки.

### Подтянуть изменения main в ветку задания

Если в `main` обновились общие настройки или добавились другие задания:

```sh
git fetch origin
git switch 12-luna
git merge origin/main
git push
```

Перед объединением сохрани текущие правки. `git merge origin/main` включает изменения
из основной ветки в текущую ветку задания. Если Git сообщил о конфликтах, исправь
указанные файлы, выполни `git add <путь>` и `git commit`, затем `git push`.
Для отмены незавершённого объединения используй `git merge --abort`.

### Временно отложить правки

| Команда | Что делает |
| --- | --- |
| `git stash push -u -m "Черновик задания"` | Убирает незакоммиченные правки во временное локальное хранилище, включая новые неигнорируемые файлы. |
| `git stash list` | Показывает отложенные наборы правок. |
| `git stash pop` | Возвращает последний набор правок в текущую ветку; при конфликте набор остаётся в хранилище. |
| `git restore --staged <путь>` | Убирает файл из подготовки к коммиту, сохраняя правки в самом файле. |

Возвращай `stash` в ту ветку, где хочешь продолжить работу. `stash` хранится только
на текущем устройстве: для переноса черновика между ПК и Mac используй `commit` и `push`.

### Завершить задание и удалить его ветку

Отправь ветку на GitHub и создай pull request в `main`. После проверки и объединения:

```sh
git switch main
git pull --ff-only
git branch -d 12-luna
git push origin --delete 12-luna
```

`git branch -d` удаляет локальную ветку и откажется удалять её, если Git считает,
что в ней остались необъединённые коммиты. `git push origin --delete` удаляет ветку
на GitHub; если она уже удалена через интерфейс GitHub, эту команду пропусти.
Эти команды выполняй только после включения задания в `main`.

Сейчас задание 12 находится в `js-basic/12-luna` в ветке `12-luna`, обновлённой
из `main`. В саму `main` задание пока не включено.
